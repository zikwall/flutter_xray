# HEV Android device test — 2026-08-14

## Environment

- device: Xiaomi 25028RN03A (`serenity`), ARM64;
- Android: 15 / API 35;
- network: Wi-Fi, IPv4 `192.168.1.14`; no global IPv6 address was assigned;
- Xray runtime reported by the packaged AAR: 26.6.1;
- HEV: 2.17.1, built from the pinned submodule with NDK 29.0.14206865;
- test profile: credential-free SOCKS inbound plus Xray `freedom` outbound.

The direct profile verifies the local Android VPN, HEV, SOCKS and Xray packet
path. It is not evidence for a remote VLESS transport.

## Results

| Scenario | Result | Evidence |
| --- | --- | --- |
| HEV JNI load/start/stop | Pass | service log selected `hev-socks5-tunnel`; IPv4 payload completed |
| IPv4 TCP | Pass | Cloudflare trace returned 205–206 bytes |
| Rapid lifecycle | Pass | 100 rapid connect/disconnect cycles, followed by a successful packet-path check and clean disconnect |
| Background and sleep/wake | Pass | 90-second hold included Home plus 20 seconds screen-off; post-wake IPv4 request returned 210 bytes |
| Measured download | Pass | 1,000,000 bytes in 1.206 seconds, 6.63 Mbit/s on this run |
| ARM64 release install | Pass | cold launch completed on the named device |
| Android 16 KB page size | Pass | final APK and all 11 inspected native libraries passed ELF and ZIP checks |
| IPv6 | Not testable on this network | only link-local IPv6 was present; direct IPv6 attempts did not complete |
| UDP | Inconclusive for HEV comparison | request reached Xray and the LAN echo server with both HEV and BadVPN, but the response did not return through the synthetic `freedom` setup |
| DNS leak | Not established | Android DoT traffic was visible through the SOCKS inbound, but a remote resolver/leak test was not available |
| H3/QUIC | Not run | requires a controlled endpoint/profile |
| VLESS gRPC, H2, H2R | Not run | requires explicit non-production test profiles |
| `blockedApps` public-IP split | Not run | a direct outbound has the same public IP inside and outside the VPN |

The UDP parity check is important: the same one-way result occurred with the
existing BadVPN backend, so this harness did not identify an HEV-specific UDP
regression. UDP remains mandatory before HEV can become the default.

## Resource snapshot

During the credential-free hold, the example app plus VPN process reported:

- before background: total PSS 223,664 KB; total RSS 314,789 KB;
- during screen-off: total PSS 225,430 KB; total RSS 311,980 KB;
- instantaneous CPU sample: 0% for both processes while idle;
- battery: 94% to 93% during the short screen-off sample.

The battery interval is too short and the device was attached over USB, so it
must not be used as a comparative power result. A controlled, longer VLESS load
test is still required for CPU, memory, throughput and battery comparison.

## Package size

The final ARM64 release example APK is 26,597,212 bytes, SHA-256
`c89ef900f3c54ee527caa849822802ba49e058e8897338cd46198c5cf0634a06`.
The pre-HEV reference was 26,279,385 bytes. The total difference is 317,827
bytes and includes the example `MainActivity` launch fix; 147,426 compressed
bytes are the packaged ARM64 HEV library.
Most of the remaining difference comes from fixing the previously unlaunchable
example `MainActivity`, so the HEV ZIP entry is the relevant single-ABI runtime
payload delta.
